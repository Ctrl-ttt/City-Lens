## 0. 执行前 60 秒读完

1. **本次访谈的定位是"证伪"，不是"证实"。** 目标是把我们想错的地方找出来，不是收集认可。三位没有否定我们，**不等于**三位认可我们，答辩时不得这样表述。
2. **时间现实**：20 分钟扣掉开场 1 分钟、收尾 3 分钟，主体只剩约 16 分钟，**实际只装得下 5 题**（每题约 3 分钟）。本提纲每场列 9 题（三场共 27 题），其中 **★ 为必问（每场 5 题，共 15 题）**，其余作为题库。
3. **放弃顺序已预先定好**：时间不足时按各场末行给出的顺序放弃。不要在场上临时决定，也不要因为"这题挺有意思"而超时——超时挤掉的是后面更重要的题。
4. 问过去，不问愿望：先问"上次是什么时候"，再谈"您想要吗"。
5. **不演示完整产品流程**（避免锚定回答），不承诺任何功能或时间点；被问"能不能做"一律回"记下来评估"。**唯一例外是 A4**——只播放两句合成语音，不放完整流程。
6. 对方的批评就是数据：不辩解，逐条记录。
7. **每场必须有一名不提问的专职记录人**（提问者记不全）。每场结束立即口述要点互相备份，24 小时内回填本文结论区与验收记录表。

## 2. 共同话术

**开场（每场照念，约 1 分钟）**

> 我们是 insta 线下赛的学生队，在做"CityLens"原型：镜头拍前方，AI 把"眼前有什么"变成一句短中文语音，比如"右前方，共享单车"。它不导航、不判断能不能过马路，只描述。想请教您的真实经验，帮我们判断设计对不对。全程约 20 分钟，对外材料只用匿名编号；可随时打断或跳过任何问题；如需录音会在开始前单独征求您同意。

**收尾（每场，约 3 分钟）**

- 只能保留一种能力——只提醒障碍 / 只念牌子 / 只说周围有什么——您留哪个？
- 有什么我们该问没问的？
- **承诺（照念）**："今天问到的内容我们会整理成一份匿名记录，定稿后发您过目；后续如果有明确进展，也会同步给您。"

> 记录时注意：第一问是**个人取舍偏好**，答案高度依赖受访者本人的生活场景，三人答案大概率不同，**不能直接当作产品范围裁剪依据**（参见 §6）。

## 3. 场次 A · 沈可（视障 · 视障团队带头人）

**取证目标**：播报句式、重复节奏、静音策略的实现细节。她每天以读屏语音工作，是"听觉负载"的头号权威。

**★ 必问 5 题**：A2、A3、A4、A6、A9 ｜ **放弃顺序**：A1 → A8 → A7 → A5

| #     | 问题                                                                                                                                                                                                      | 验证的设计点                                                                                                 |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| A1    | 最近一次通勤在路面上停下来是因为什么？怎么发现的？                                                                                                                                                        | 事实基线，填验收表"场景与困难"                                                                               |
| A2 ★ | 路面信息现在靠什么——杖、导航、问人、听声？各自最不放心的时刻？                                                                                                                                          | 缺口清单                                                                                                     |
| A3 ★ | 整天听读屏语音：什么语速和节奏能听一天不累？现有导航 App 语音哪里最烦？                                                                                                                                   | TTS 语速、音色、打断策略                                                                                     |
| A4 ★ | （**播放后端真实 TTS 合成的这两句**，不要人声念）A："右前方，共享单车，占道。" B："注意，您右前方约三米处有一辆共享单车，请注意避让。" 哪句先反应过来？B 里的"约三米"，您觉得是机器在量，还是在猜？ | 只能确认**句式读起来是否拗口**；**不得**据此宣称"12 字句式规范成立"（见 §6）                    |
| A5    | 先问事实：上一次导航 App 反复播报把您念烦是什么情况，您当时怎么处理的？→ 再问偏好：如果我们的提示一直重复同一句，您希望隔多久、或在什么情况下才再念？                                                    | 8 秒去重的参考依据；打断策略（取值须靠实测）                                                                 |
| A6 ★ | 走路时戴什么耳机？开放式/骨传导的真实体验？有没有"绝对不戴耳机"的路段？                                                                                                                                   | 开放式单耳设计——**若否定需重议**，故列为必问                                                         |
| A7    | 最近一次找入口、门牌、会议室费劲是什么时候？念牌子这件事，想按一下再念还是它自己念？                                                                                                                      | 看牌模式触发方式                                                                                             |
| A8    | 您团队里新失明和先天失明的同事，对"机器说'可能/大概'"接受度一样吗？年长同事呢？                                                                                                                           | uncertain 表述的分层                                                                                         |
| A9 ★ | 先交底：我们现在的做法是"没看清就什么都不说"，代价是有时需要的信息它不给。这个取舍您能接受吗？还是宁可它说"没看清"？另外，它说"可能有个台阶"，您敢信吗？                                                  | **确认取舍**（不是待验证项）："失败即静默"已在代码中实现，本题是确认用户能否接受，而不是重新决定做不做 |

执行提示：先问经验再谈产品，全程不演示完整流程；A4 只放两句合成语音，放完即停，不要顺势演示其他功能。收尾两问见 §2。

## 4. 场次 B · 金光亮（视障 · 科技公司创始人）

**取证目标**：竞品格局、技术现实感、买单意愿，检验"这是 demo 还是产品"。

**★ 必问 5 题**：B2、B3、B4、B5、B8 ｜ **放弃顺序**：B7 → B6 → B9 → B1

> B1 用于暖场，建议仍先问；它与 A1/A2 属同类问题、信息增量最低，极端缺时间时才跳过。

| #     | 问题                                                                                                                                                                       | 验证的设计点                                      |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| B1    | 您作为创始人每天跑客户，路面信息缺口最大的一次具体是什么时候？                                                                                                             | 事实基线                                          |
| B2 ★ | **先亮我方判断**："我们看了 Be My Eyes、Seeing AI 和几个国产 App，我们认为 XX 是它们的死穴——您同意吗？我们哪里看错了？" 再问：哪些您真用过？哪个功能"就该这么做"？ | 竞品对照表（我方判断的纠偏，而非让对方从零介绍）  |
| B3 ★ | "走路时耳边主动、低频地报障碍"这个位置，在您用过的产品里有人占住吗？没有的话——是没人想到，还是被验证过不行？                                                             | 定位唯一性                                        |
| B4 ★ | 云端多模态方案，您能接受的延迟上限是多少？网络不稳时宁可沉默还是报错？大模型"一本正经编一个不存在的障碍"，出现率到多少您会弃用？                                           | P90 目标；错误策略；幻觉容忍度                    |
| B5 ★ | 我们现在的做法是"没看清就什么都不说"。您选这个，还是宁可它说"可能有个台阶"？                                                                                               | **确认取舍**（跨场交叉验证 A9，非待验证项） |
| B6    | 同样的镜头：装导盲杖上端、导盲犬鞍具、胸挂——您戴哪个？另外，手机后置摄像头平举是不是其实更现实？                                                                         | 三形态提案；是否漏了第四形态                      |
| B7    | 做成产品的话心理价位是多少（一次性/订阅）？身边视障朋友普遍能接受的价格？                                                                                                  | BOM 与定价叙事                                    |
| B8 ★ | **先亮我方草稿**："我们目前打算砍掉语音导航和文字播报，只留一句场景描述——您觉得砍错了吗？如果您的公司立项做这个，第一个砍掉的功能是什么？最先把哪件事做到极致？"   | MVP 范围裁剪                                      |
| B9    | 一个新辅助工具，从第一次试用到敢带它上路，中间要过几道坎？                                                                                                                 | 信任建立路径                                      |

执行提示：预期会被狠批，不辩解，批评逐条记下。收尾见 §2，另请对方补"给学生团队一句最想说的话"作为答辩素材。

**取证目标**：人群代表性、社会接受度、推广路径、公益叙事校准。她不是用户，不问走路细节。

**★ 必问 5 题**：C1、C2、C4、C6、C7 ｜ **放弃顺序**：C9 → C8 → C5 → C3

> C8 若被放弃，会后改用邮件跟进合作意愿，不要就此丢掉线索。

| #     | 问题                                                                                                              | 验证的设计点                                                                               |
| ----- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| C1 ★ | 从全国助残工作的视野看，视障群体城市出行最普遍、最没被解决的困难是什么？和"科技圈的想象"差最远的是哪个？          | PRD 问题定义                                                                               |
| C2 ★ | 先天失明、新失明、老年低视力、多重障碍——"一句短语音 + 镜头朝前"的设计，哪类人群用不上？最容易被我们忽略的是谁？ | 用户范围与优先人群                                                                         |
| C3    | 辅助设备带镜头上街会拍到路人：从社区反馈看，视障用户和被拍路人各自的顾虑？您见过因为镜头引发的实际纠纷吗？        | 社会性设计（产品形态 §5）。**不要问"我们的镜头指示灯够不够"**，那是征求认可而非取证 |
| C4 ★ | 这类产品要真正到达社区，一般走什么渠道——残联、协会、政府采购、公益捐赠？机构背书前必须看到什么证据？            | 推广路径与验收证据                                                                         |
| C5    | "只描述、不建议通行"这条线，在机构角度看是否足够？现实中用户过度信赖辅助工具出了事，通常是怎么归责的？            | 边界声明的现实风险                                                                         |
| C6 ★ | 您见过哪些"为残障人士设计"最后失败的产品？共性错误是什么？                                                        | 反设计清单校准                                                                             |
| C7 ★ | 答辩和公益评审场合，关于残障群体的表述哪些话您听了会觉得不对劲？该怎么换说法？                                    | 叙事措辞                                                                                   |
| C8    | 学生原型阶段，协会愿意以什么形式参与——试用反馈、专家指导、场景对接？需要我们提供什么？                          | 后续合作                                                                                   |
| C9    | 如果只够服务好一小群人，该先服务谁——通勤上班族，还是老年低视力群体？                                            | 优先人群                                                                                   |

## 6. 防止结论被过度外推

以下结论极容易在整理与答辩时被讲过头。回填验收记录时，**必须**按"实际能得出的结论"一栏写。

| 题目       | 容易讲成的结论                               | 实际能得出的结论                                                                                                                  |
| ---------- | -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| A4         | "12 字句式规范得到用户验证"                  | "一位受访者认为，用 TTS 播放的 A 句比 B 句更容易第一时间反应过来。" 样本 1 人、安静环境、非行走状态，**不足以支撑规范成立** |
| A5、A6     | "去重间隔应设为 N 秒" / "确认采用开放式单耳" | A5 只能得到个人偏好，**最终取值须靠实测**；A6 若被否定是一票**否决性**证据（设计需重议），若被肯定也不构成采纳理由    |
| C2、C4、C6 | "协会认可产品方向" / "已有推广渠道"          | "一位从业人员看到的普遍困难与渠道常识"。C 场受访者**不是用户**，其意见不能代表用户群体，也**不构成任何机构背书**      |
| 收尾第一问 | "用户最需要 XX 功能"                         | "这一个人，在这个阶段，最舍不得放下哪一项"，不能当产品范围裁剪依据                                                                |

## 7. 访谈后回填规则

1. 当天（2026-09-22）内完成要点整理，24 小时内回填 [验收记录](验收记录.md) 三行表（匿名编号/场景与困难/当前应对/受访者观点/据此调整的设计/日期与记录人）。**记录人代号必须写明**；只写"团队"不算记录。
2. 回填时逐条对照 §6，确认没有把结论讲过头。
3. 对照检查三块是否有推翻性意见：句式规范（A）、产品定位（B）、叙事措辞（C）；有的话当天修改 [产品形态与包装](产品形态与包装.md)，答辩前必须消化完。
4. **A9 与 B5 是"确认取舍"而非"待验证项"。** "失败即静默"已在代码中实现，若受访者明确否定，只有两种正当处理：

   - (a) 真的改；或
   - (b) 在 [架构决策记录](架构决策记录.md) 写明"用户倾向 X，团队基于 Y 仍选择静默"，并说明这是明知取舍。

   **不得只记录不改、也不写理由**——那样这次询问就是走过场。
5. 结论定稿后**发回给受访者过目**（收尾已作承诺）。这一步同时是纠错机会与关系维护，不要跳过。
