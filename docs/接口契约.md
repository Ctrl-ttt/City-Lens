# API 契约 v0.1

> 实现事实来源：`backend/models.py`、`backend/app.py` 和契约测试。字段语义与保留策略见 [数据模型与数据治理](数据模型与数据治理.md)，架构边界见 [架构与云端边界](架构与云端边界.md)。
>
> 当前契约适用于本地可信来源。ECS 公网部署前，必须把可信主机和允许来源改为受环境配置控制，并为正式 HTTPS 域名补充测试；不得通过放开任意来源来绕过部署限制。

服务：localhost:8000。模型适配在同一 Python 服务中；无数据库，不保存输入帧。响应包括 `Cache-Control: no-store`（识别接口）。

## GET /api/health

```json
{"status":"ok","provider":"sample","configured":true,"model":"fixed-sample","sample_scene":"bicycle","version":"0.1.0"}
```

`configured` 只检查配置存在，不发模型请求；live 时 `sample_scene=null`。不返回密钥。

## POST /api/analyze

multipart/form-data，必须且仅包含以下五个字段（不能重复）：

| 字段 | 要求 |
|---|---|
| image | JPEG 文件、image/jpeg、最大 2 MiB；图片必须可解码，最多 1200 万像素 |
| mode | walk / read |
| source | camera / video |
| session_id | 1–80 字符，仅字母、数字、下划线、短横线 |
| frame_id | 0 到 2147483647 的整数 |

```json
{
  "session_id":"demo-001","frame_id":1,"status":"ok",
  "events":[{"category":"obstacle","label":"bicycle","direction":"right","text":"自行车"}],
  "speech":{"key":"bicycle:right","priority":"high","text":"右前方发现自行车"},
  "latency_ms":1800,"error_code":null,"message":null
}
```

类别 `obstacle/facility/text`；方向 `left/front/right/unknown`；状态 `ok/uncertain/error`。
无事件时 `events=[]`、`speech=null`，不输出通行结论。看牌不清晰时 `status=uncertain`，候选文字为“文字看不清，请调整拍摄角度”。优先级由服务代码决定。

受控错误返回相同响应外壳、空事件、无播报、`error_code` 和中文 `message`。解析到元数据前的错误可能返回空 session_id 和 frame_id=0。

| 状况 | HTTP / error_code |
|---|---|
| 无配置 | 200 / not_configured |
| 模型认证失败、限流或暂不可用 | 200 / model_auth、rate_limited、model_unavailable |
| 超时、网络或格式错误 | 200 / model_timeout、network_error、invalid_model_output |
| 请求字段或图片无效 | 422 / invalid_input |
| 图片/总请求超限 | 413 / image_too_large |
| 上次模型请求未完成 | 429 / busy |
| 不在允许列表的网页来源 | 403 / forbidden_origin |
| 服务内部异常 | 500 / internal_error |

前端须同时检查 HTTP 状态和业务 `status`，不得朗读原始错误。walk 从该帧 capture 起超过 6 秒、read 超过 8 秒的结果作废。切换输入、暂停、拖动、模式变化生成新 session_id；HTTP 返回结果必须匹配当前请求的 session_id 和 frame_id。后端全局最多一个模型调用，切换会话后的短暂 busy 属于正常拒绝竞争行为。

HTTP 与实时连接的 `walk` 均自动提取可读路牌、门牌及方向指示牌，并保留障碍与设施；`read` 仅保留最清晰的一块标牌，不含障碍或设施。主动看牌仍关闭实时连接，以较高分辨率单帧通过 HTTP 请求。HTTP 模型为 `qwen3-vl-plus`，当前默认实时模型为 `qwen3.5-omni-plus-realtime`。HTTP 自动抽帧每 2 秒尝试一次且 single-flight，忙时跳过；模型端总超时仍为 8 秒，不自动重试旧帧。实时自动观察的连续发送与最新槽规则见下节；两者的采样间隔都不是响应时延保证。

## WebSocket /api/realtime

**连续帧流只发生在浏览器 → 后端；不是云端双工输入、30fps 或多图合并生成。** 实现事实来源为 `backend/app.py`、`backend/realtime.py`、`backend/models.py`、`frontend/src/realtime.ts` 和 `frontend/src/App.tsx`。

### 消息与限制

同源 `ws://`（HTTPS 页面为 `wss://`）。Origin 必须精确匹配本机 8000/5173 允许列表，否则以 1008 拒绝；样例供应商不提供实时链路。上游初始化完成后后端发送 `{"type":"ready"}`；浏览器只能在 ready 后 capture/发送。

客户端发送 JSON 文本消息，必须且仅包含以下字段，不接收二进制帧或 data URL：

| 字段 | 要求 |
|---|---|
| `type` | `frame` |
| `session_id` | 同 HTTP 格式；同一连接内固定 |
| `source` | `camera` / `video`；同一连接内固定 |
| `frame_id` | 0～2147483647；同一连接严格递增，允许跳号；页面生成帧号从 1 开始 |
| `mode` | 仅 `walk`；主动看牌仍走 HTTP |
| `image` | JPEG 的纯 base64，编码字符串 ≤256KiB（不是解码后的图片大小） |

整条消息 ≤256KiB + 2048 字符；JPEG 必须可解码、最多 1200 万像素。后端移除元数据、转 RGB、最长边缩至 960、质量 65 重编码，送云前再次检查编码后 ≤256KiB。无效 base64/JPEG/字段为 `invalid_input`；清洗后仍超云端编码限额为 `realtime_image_too_large`。

自动观察在 ready 后约 1fps 持续发送，**不等待 result**；客户端检查实际发送间隔 ≥1s 且 `bufferedAmount===0`，未 ready、节流或背压时直接跳过，不 capture、不建立图片队列。仅保留最多 16 条已发送帧的 `session_id`/`frame_id`/`capturedAt` 元数据；不保留待重传图片。服务端两次接收间隔小于 0.9s 返回 `rate_limited` 并关闭，不排队重试。

### 接收、选择与结果归属

`backend/app.py` 同时运行两个任务：

- `receive_frames` 持续接收、验证会话/来源/递增帧号和限速、清洗 JPEG，把 `(image, meta, received_at)` 放入 `Queue(maxsize=1)`；满槽时替换旧待分析图。
- `process_frames` 从槽取最新图，持有全局模型锁，串行调用 `RealtimeVision.observe(image)`；上传、生成、删除确认全部完成后返回结果，再取下一张。生成和清理期间接收任务仍可更新槽，但不向云端发送新图。

应用分析状态最多 **一张分析中 + 一张最新待分析**，不是 FIFO 图片积压。已 ready 的当前会话接收不会因为自身生成而 `busy`；与 HTTP 竞争全局模型锁才 `busy`。另有独占实时会话锁：第二条 WebSocket 或 ready 前发送也会被 `busy` 拒绝。HTTP 请求竞争同一模型锁时仍返回 429 `busy`。

结果为 `{"type":"result", ...AnalyzeResponse}`，沿用受限事件和播报规则。`result.frame_id` **标记实际被选中并分析的那一张图**：例如分析 1 时收到 2、3，3 替换 2，可以只返回结果 1、3。它不是多图 commit 的最新边界，也不保证是结果抵达时浏览器最后发送的帧。

实时 `latency_ms` 从该帧后端接收时间起算，包含校验/清洗、待分析槽停留、上传、响应和清理确认，不含此前的 capture/网络传输。前端按结果帧号取对应 capture 时间，从 capture 起执行自动观察 6s 过期，不能用 result 到达时间或其它帧时间续期；HTTP 看牌仍为 8s。外会话、未发送、重复、倒序或已淘汰元数据的结果均忽略；接受结果后移除不大于该帧号的元数据，跳过帧不会重传。

### 超时、取消与恢复

| 范围 | 当前行为 |
|---|---|
| 后端每次 `observe` | generation 整体 8s，含上传、响应与删除确认；不是每一步各 8s |
| 前端握手 | 等待 ready 最多 15s，期间不 capture |
| 前端进展看门狗 | 有待返回帧时，9s 无有效新结果进展即断开；继续发送、外会话或重复结果不延后期限；有效进展刷新，已无待返回帧则清除 |
| 有限重连 | 可重试错误按 1/2/4s 至多重连 3 次；ready/result 均不重置预算，用户重新开始才重置；每次只采新图 |
| 后端空闲/会话 | 等待下一张待分析图 30s 超时为 `realtime_idle`；会话 110min 上限在处理循环检查，到期为 `realtime_expired` |
| 取消 | 暂停、停止、输入/模式/通道切换、拖动、页面隐藏、Link 2 控制均作废旧结果和语音、关闭连接；后端取消接收/处理任务并释放锁，不重传旧图 |

错误消息为 `{"type":"error","error_code":"…","message":"受控中文提示"}`，随后关闭连接，不返回供应商原文。除通用模型/输入错误外，实时链路还有 `realtime_unavailable`、`realtime_protocol`、`realtime_image_too_large`、`realtime_idle`、`realtime_expired`。客户端仅对 `network`/`network_error`、`model_timeout`、`model_unavailable`、`realtime_expired`、`busy` 自动有限重连；其它错误终止并提示人工处理或切换 HTTP，无样例回退。

### 云端手动协议与实测边界

[官方 Python SDK](https://www.alibabacloud.com/help/en/model-studio/omni-realtime-python-sdk)要求手动模式（`turn_detection=null`）在模型响应期间停止音视频输入。当前每次 observe 发送合成 PCM 静音 200ms 前导 → 一张图 → 1s 尾音 → `input_audio_buffer.commit` → `response.create`，校验完整文本和 `response.done` 后发送 `conversation.item.delete` 并等待 `conversation.item.deleted` 确认，再允许下一张上云。**不采集麦克风。**

真实 API 已证伪先前重叠输入方案：在 `response.created` 后继续送图、`response.done` 后再 commit 报 `buffer too small`；VAD 模式也丢弃纯静音，不能靠直接改 VAD 在无麦克风条件下解决。1s 尾音及 delete/ack 是当前模型兼容实测，不是供应商长期稳定承诺，也不保证历史绝不影响下一轮。模拟上游接受重叠不等于真实协议支持；本轮新版 E2E 与真实摄像头验收不得由这些证据代替。

## Observation 清晰度与标牌规则

`Observation.clarity` 严格限定为 `"high"`、`"medium"`、`"low"` 或 `null`。`category=text` / `label=sign` 必须携带非空枚举值；其它类别只可省略或填 `null`。标牌的 `clarity` 缺失或为 `null`、非文字事件的 `clarity` 非空或任何枚举外值均为 `invalid_model_output`。

| clarity | 模型视觉判断 | 服务端处理 |
|---|---|---|
| `high` | 大字、字形干净，所选文字完整且清楚可读 | 可进入事件及播报候选 |
| `medium` | 文字较小，但所选文字仍完整可读 | 可进入事件及播报候选，排在 high 标牌后 |
| `low` | 模糊、缺字或有不确定内容 | 从事件与播报候选中排除，不猜测补全 |

清晰度是模型的视觉定性判断，不是距离估计或经校准的准确率；不增加测距、导航或安全通行结论。

事件排序：台阶/楼梯 → 其它障碍物 → high 标牌 → medium 标牌 → 设施；同级保留原顺序。标牌文字去除首尾空白、连续空白合并为一个空格后按相同文字去重，忽略方向与清晰度；排序、去重后 `walk` 最多 3 项，`read` 最多 1 项。看牌无可读标牌时提示看不清，不用 low 文字生成事件或播报。

每帧仅首项事件生成 `speech`，不是逐项播报：障碍优先级 `high`（可打断），标牌 `normal`，设施 `low`。标牌 `speech.key` 为 `sign:<text>`，其中 `<text>` 为规范化空白后的文字，不含方向或清晰度。自动播报沿用 8 秒去重，手动触发绕过去重；若首项障碍重复而被抑制，不改播该帧次项标牌，标牌可能等后续帧成为首项才播报。

## Link 2 本地 SDK 控制

`GET /api/camera/link2` 与 `POST /api/camera/link2` 必须携带 `X-CityLens-Camera: 1`。网页 Origin 仅允许本机 8000/5173，拒绝跨站请求；不启用 CORS。所有响应包含 `Cache-Control: no-store`。此接口不采集或上传视频，不调用模型。

GET 返回 `{"status":"ready","devices":[{"id":"…","name":"Insta360 Link 2"}]}`。设备 ID 是不透明的小写十六进制串，长度 2～4096、字符数为偶数；客户端必须使用枚举结果，不依赖设备顺序。无设备返回空数组，不伪造连接成功。

POST 使用 `application/json`，总请求最多 8192 字节，必填 `device_id` 和 `action`，其余字段必须恰好匹配动作，不接受多余字段、数值字符串或空值：

| action | 额外字段 | 成功响应 |
|---|---|---|
| status | 无 | `status=ok`，以及 `ptz`、`zoom`、`autofocus` |
| ptz | 整数 `pan`：−145～145；整数 `tilt`：−45～90，单位度 | `{"status":"ok","accepted":true}` |
| zoom | 整数 `zoom`：0～65535，且符合设备返回的 min/max/step | 同上 |
| autofocus | 布尔 `enabled` | 同上 |

状态示例：`{"status":"ok","ptz":{"pan":0,"tilt":0},"zoom":{"min":100,"max":400,"step":10,"value":100},"autofocus":true}`。示例变焦范围不代表所有固件；查询失败的能力单独为 `null`，前端禁用对应控件。云台角度是设备坐标，不是使用者朝向。API 的 `pan` 始终表示水平、`tilt` 始终表示俯仰；原生桥接按 Link 2 真机反馈，将 SDK 读取和设置的两个轴参数映射为 `(tilt, pan)`，不直接沿用 SDK 参数命名。

错误外壳为 `{"status":"error","code":"…","message":"中文提示"}`：403 `forbidden_origin`、422 `invalid_input`、404 `device_not_found`、409 `busy`、503 `sdk_missing/sdk_failed/sdk_timeout`。不返回 SDK 原始诊断或设备路径。原生进程最长运行 8 秒，全局串行、不排队；HTTP 取消不提前释放尚在执行的原生命令。

前端仅在当前预览与浏览器、SDK 枚举都唯一匹配 Link 2 时允许控制。控制前作废识别会话、语音和旧画面结果，进行中禁止重新识别；成功响应只表示接受命令，必须由使用者确认画面稳定，不能据此断言云台已到位或导航方向安全。

## 兼容性与变更规则

- `v0.1` 中字段均为受控字段，客户端不得依赖未文档化的额外字段或模型原始响应。
- 新增标签、类别、方向、必填字段、错误码或请求方式时，必须同时更新 Pydantic 模型、前端类型、规则、本文档和测试。
- 删除或改变既有字段语义属于破坏性变更；必须提高接口小版本，提供迁移说明，并在旧版本客户端完成迁移前保留兼容路径。
- `distance`、经纬度、用户身份、路线指令和“是否安全通行”等字段不属于本接口。相关需求应先通过 ADR、安全评估和独立测试后再讨论。
