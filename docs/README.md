# CityLens 文档中心

本目录记录 CityLens 的产品边界、工程契约、验证证据与交付过程。文档描述的是可复查的约定；除非 `PROGRESS.md` 或验收记录明确标为已完成，计划和待验证事项均不应被表述为已实现能力。

## 阅读路径

| 文档 | 解决的问题 | 何时更新 |
|---|---|---|
| [PRD.md](PRD.md) | 为谁解决什么问题、MVP 做什么、不做什么、怎样验收 | 用户场景、范围或成功标准改变时 |
| [ARCHITECTURE.md](ARCHITECTURE.md) | 当前实现与目标云端部署的组件边界、数据流和安全边界 | 接入新服务、相机或部署方式改变时 |
| [API.md](API.md) | 浏览器与后端之间的 HTTP 契约 | 请求、响应、错误码或兼容性改变时 |
| [DATA_MODEL.md](DATA_MODEL.md) | 瞬时数据、评测数据、OSS 对象和未来持久化数据的模型 | 字段、保留期限、存储方式改变时 |
| [TEST_STRATEGY.md](TEST_STRATEGY.md) | 自动化、人工、设备、模型和发布测试如何设计 | 风险、测试范围或门槛改变时 |
| [OPERATIONS.md](OPERATIONS.md) | ECS、OSS、RAM、密钥、发布、回滚和现场备用方案 | 环境、权限、域名或运行方式改变时 |

| [VALIDATION.md](VALIDATION.md) | 用户访谈、真实模型、设备与流程的人工验收记录 | 每次真实验证后 |
| [PROGRESS.md](PROGRESS.md) | 已完成事项、验证证据、已知限制和下一步 | 每次可验证的工作完成后 |

## 文档优先级与维护规则

1. `backend/models.py`、`frontend/src/types.ts` 和已通过的测试是当前接口字段的实现事实；`API.md` 是对外协作契约。两者不一致时，先修复不一致再继续开发。
2. `PRD.md` 是产品范围的事实来源；没有写入 PRD 的新功能不得在临近演示时直接加入主流程。
3. `DECISIONS.md` 记录“为什么这样做”；不要只在聊天记录或口头同步中保留重要理由。
4. 涉及真实用户、图像、视频、模型调用成本或云端权限的变更，必须同时检查 `DATA_MODEL.md`、`TEST_STRATEGY.md` 和 `OPERATIONS.md`。
5. 使用 RFC 2119 含义：**必须**表示发布前不可缺少，**应该**表示有充分理由才可例外，**可以**表示可选增强。

## 建议的变更流程

```text
用户问题 / 赛题要求
        ↓
PRD：确认目标、范围和验收条件
        ↓
Architecture + API + Data Model：确定边界与契约
        ↓
Test Strategy：先写可验证的测试点
        ↓
实现、评审、自动化测试
        ↓
真实模型 / 设备 / 用户验证
        ↓
PROGRESS + VALIDATION：记录事实与剩余风险
```

## 版本约定

- MVP 接口当前为 `v0.1`；任何破坏前端兼容性的 API 变化必须提高小版本并写明迁移方式。
- 文档顶部没有特别标注时，默认适用于仓库当前主分支。
- 所有真实密钥、含可识别信息的图像、原视频、访谈录音和私有 OSS 地址都不得写入本目录。
