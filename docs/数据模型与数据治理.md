# CityLens 数据模型与数据治理

| 字段 | 内容 |
|---|---|
| 版本 | v0.1 |
| 更新日期 | 2026-09-22 |
| 原则 | MVP 默认不建立用户业务数据库，也不持久化实时输入帧 |

## 1. 当前数据状态

当前 MVP 的数据设计是**瞬时处理优先**：浏览器生成会话和帧编号；后端在内存中校验 JPEG、调用模型、返回受控事件；语音队列和并发锁只在进程内存中存在。服务重启、页面刷新或会话切换后，这些状态均不会保留。

这个选择是有意的：CityLens 的 MVP 目标是验证环境理解与播报流程，不需要账号、行程历史或用户画像。没有明确的用户价值、授权流程、保留期限和安全方案前，不新增数据库。

## 2. 运行时契约模型

实现事实来源为 `backend/models.py`，对外字段见 [接口契约](接口契约.md)。

### 2.1 HTTP 分析请求 `AnalyzeInput` 与上传文件

| 字段 | 类型 / 约束 | 含义 | 是否持久化 |
|---|---|---|---|
| `session_id` | 1–80 位字母、数字、`_`、`-` | 一次连续输入生命周期的隔离标识 | 否 |
| `frame_id` | 非负 32 位整数 | 同一会话内递增帧号 | 否 |
| `mode` | `walk` / `read` | 行走环境理解或主动看牌 | 否 |
| `source` | `camera` / `video` | 摄像头或本地视频 | 否 |
| `image` | JPEG，最大 2 MiB，最多 1200 万像素 | 当前单帧；multipart 文件，不是 `AnalyzeInput` 内的字段 | 否；仅请求处理期间存在 |

HTTP 自动观察每 2s 尝试一帧、single-flight，不排队重试旧图；主动看牌仍走较高分辨率 HTTP。这不限制实时浏览器链路同时存在多个尚未返回结果的帧编号。

### 2.2 实时输入 `RealtimeFrame` 与有界瞬时状态

**实时连续帧流指浏览器 → 后端，不是云端双工或 30fps。** `RealtimeFrame` 继承请求元数据，增加 `type=frame`、纯 base64 JPEG `image`，并限定 `mode=walk`。同一连接内 `session_id` 与 `source` 固定、`frame_id` 严格递增，允许跳号；切换来源/会话须关闭旧连接。

- 编码后的 JPEG 字符串 ≤256KiB（非解码字节数），消息总长 ≤256KiB + 2048 字符；拒绝 data URL、无效 base64、不可解码或超过 1200 万像素的 JPEG。后端清洗为 RGB、移除元数据、最长边 960、质量 65，送云前再检查编码限额。
- 自动观察在 ready 后按 1fps 持续向后端发送，不等 result；客户端发送间隔 ≥1s，背压或未 ready 时不 capture、不建立图片队列；服务端接收间隔至少 0.9s。
- 浏览器最多保留 16 条已发送帧元数据：以 `frame_id` 为键，值仅有会话与 `capturedAt`，不包含图片；过多淘汰最旧记录，取消/断开时清空，重连只采新图。
- 后端 `receive_frames` 持续校验/清洗，保存 `(image, meta, received_at)` 到 `Queue(maxsize=1)`，新图替换旧待分析图；`process_frames` 取最新图串行调用 `RealtimeVision.observe(image)`。应用分析状态最多一张分析中 + 一张最新待分析，生成/删除确认期间仍接收但不向云端发新图；自身生成不让接收返回 busy，与 HTTP 竞争模型锁才 busy。
- `result.frame_id` 对应实际被选中的单张图。例如分析 1 时 3 替换待分析 2，可返回 1、3 而无 2；不是多图 commit 的最新边界。浏览器按该帧元数据核对会话、时效，忽略未发送、外会话、重复、倒序或已淘汰记录的结果；接受结果后移除不大于该编号的元数据，不补发跳过帧。

后端单轮 generation 包含上传、响应、清理确认，整体 8s；前端 ready 15s、存在待返回帧时 9s 无有效新结果进展断开，继续发帧不延后看门狗。可重试错误按 1/2/4s 最多重连 3 次，ready/result 不重置预算；后端等待待分析图空闲 30s、会话限 110min。暂停、切换、页面隐藏及 Link 2 控制会作废旧状态并关闭连接，不保存待恢复图片。

### 2.3 观察事件 `Observation`

| 字段 | 类型 | 规则 |
|---|---|---|
| `category` | `obstacle` / `facility` / `text` | 类别必须与 `label` 对应 |
| `label` | 受控短字符串 | 当前允许 `bicycle`、`barrier`、`bollard`、`step`、`stairs`、`escalator`、`obstacle`、`crosswalk`、`elevator`、`entrance`、`bus_stop`、`sign` |
| `direction` | `left` / `front` / `right` / `unknown` | 指未镜像画面中的相对位置，不是地图朝向 |
| `text` | 最多 80 字 | `text/sign` 为所选标牌文字，不臆测补全；仅 high/medium 可进入响应；其它类别由服务端覆盖成受控中文标签 |
| `clarity` | 严格限定为 `"high"` / `"medium"` / `"low"` / `null` | `text/sign` 必须提供非空枚举值；非文字事件仅可省略或填 `null` |
| `box` | `[x1,y1,x2,y2]` 或省略 | 0-1000 归一化坐标（左上角原点），框住该项主体；畸形值只丢框不丢事件，仅用于标注/调试 |

标牌清晰度由模型对画面作视觉定性判断：`high` 为大字、字形干净、所选文字完整清楚可读；`medium` 为文字较小但所选文字仍完整可读；`low` 为模糊、缺字或不确定。服务端从事件与播报候选中排除 `low`，不会因其文字存在就读出。这不是距离估计或经校准的准确率，仍需真实素材人工核验。

模型不能返回精确距离、绝对坐标、路线、身份、人脸、自由格式建议或未定义字段；唯一允许的坐标是 `box` 归一化框。任何不符合模型约束的上游内容都会作为 `invalid_model_output` 处理，包括标牌的 `clarity` 缺失或为 `null`、非文字事件携带非空 `clarity` 或任何枚举外值。

### 2.4 分析响应 `AnalyzeResponse`

| 字段 | 含义 | 数据治理要求 |
|---|---|---|
| `session_id` / `frame_id` | 本次实际被分析帧的会话与编号 | 实时帧允许因最新槽替换而跳号，不代表多图 commit 边界 |
| `status` | `ok`、`uncertain`、`error` | 不能由前端猜测；错误时不保留上一次可播报事件 |
| `events` | 排序去重后，`walk` 最多 3 项，`read` 最多 1 项 | HTTP 与实时行走模式均包含障碍、可读路牌/门牌/方向指示牌和设施；看牌只保留最清晰标牌 |
| `speech` | 仅首项事件的一条可播报文本或 `null` | 前端仍需检查会话与时效；自动播报 8 秒去重，手动触发绕过去重 |
| `latency_ms` | HTTP 从后端请求处理开始；实时从被选帧后端接收起算，含清洗、槽等待、上传、响应及清理确认 | 可作为匿名性能指标；不等于浏览器 capture 起的端到端耗时 |
| `error_code` / `message` | 受控错误码和面向用户的中文信息 | 不应包含密钥、上游响应体或图像内容 |

前端按该帧 `capturedAt` 执行自动观察 6s / HTTP 看牌 8s 过期，不能用 `latency_ms`、其它新帧或结果抵达时间刷新旧结果的有效期。

事件按台阶/楼梯 → 其它障碍 → high 标牌 → medium 标牌 → 设施（含扶梯、电梯）排序，同级保留原顺序。标牌文字去除首尾空白、连续空白合并为一个空格后，以文字去重，不区分方向或清晰度；先排序再去重、限量。`read` 不返回障碍或设施，仍采用较高分辨率的单次 HTTP 看牌流程。

标牌播报键为 `sign:<text>`（规范化后的文字），优先级 `normal`；障碍为可打断的 `high`，设施为 `low`。每帧仅首项事件可生成播报，重复首项障碍被自动去重抑制时，不改播同帧其它事件；标牌可能要等后续帧才成为播报候选。`clarity` 的 high/medium/low 是文字清晰度，不是语音优先级。

### 2.5 云端音频与历史清理边界

当前不采集麦克风，只发送合成 PCM 静音（200ms 前导 + 每图 1s 尾音）。按[官方手动时序](https://www.alibabacloud.com/help/en/model-studio/omni-realtime-python-sdk)，`turn_detection=null` 时生成期间停止音视频输入；一张图上传、commit/生成、完整文本校验及 `conversation.item.delete`/`conversation.item.deleted` 确认结束后，才取下一张待分析图上云。

真实 API 测试中，在 `response.created` 后送图、`response.done` 后再 commit 失败 `buffer too small`；VAD 也会丢弃纯静音，不能在无麦克风条件下直接改 VAD 解决。1s 尾音与 delete/ack 属当前模型兼容实测，不是供应商稳定协议承诺；删除确认不证明供应商已消除所有数据副本，也不保证历史绝不影响结果。应用不记录图片、音频、OCR 全文或上游原文；供应商留存政策须独立核实。合成图与模拟测试不能替代本轮新版 E2E、真实摄像头及隐私验收。

## 3. 评测数据模型

真实模型评测需要可复现的期望结果，但原始图像不应进入 Git。建议在被 `.gitignore` 忽略的 `local-data/evaluation/` 内维护：

```text
local-data/evaluation/
├─ images/                 # 授权图片；不提交代码仓库
├─ manifest.csv            # 测试清单；可去标识后另行共享
└─ results-YYYY-MM-DD.csv  # 每次真实模型运行的结果
```

`manifest.csv` 建议字段：

| 字段 | 示例 | 说明 |
|---|---|---|
| `case_id` | `walk-001` | 不含姓名、地点或文件原名的匿名 ID |
| `split` | `debug` / `frozen` | 调试集可以帮助调参；冻结集在规则和提示词冻结后才运行 |
| `mode` | `walk` / `read` | 预期交互模式 |
| `expected_events` | `stairs:front` | 运行前人工标注的核心事实 |
| `expected_text` | `仙林大道` | 仅必要的清晰文字；避免收录私人信息 |
| `consent_ref` | `C-20260922-01` | 授权记录的内部编号，不在公开仓库存放原始授权文件 |
| `expires_on` | `2026-10-22` | 素材的复核或删除日期 |

`results-YYYY-MM-DD.csv` 建议字段：`run_id`、`case_id`、`model`、`status`、`actual_events`、`actual_text`、`latency_ms`、`result`、`reviewer`。模型名、时延和错误码可以记录；原始请求图片、API Key、完整上游返回体不得记录。

## 4. OSS 对象模型

OSS 不是实时帧的必经组件。仅在素材管理和故障备用确有需要时使用私有 Bucket，并使用稳定、无个人信息的键名：

```text
citylens-demo-<team>/
├─ demo-videos/<version>/route-backup.mp4
├─ demo-images/<version>/<case-id>.jpg
├─ route-assets/<version>/...
├─ outputs/<run-id>/summary.json             # 可选，只存去标识汇总
└─ temp/<date>/<random-id>.jpg               # 可选，短期临时对象
```

| 前缀 | 默认可见性 | 保留策略 | 说明 |
|---|---|---|---|
| `demo-videos/`、`demo-images/` | 私有 | 由素材负责人复核后保留或删除 | 必须有拍摄/使用授权 |
| `route-assets/` | 私有 | 与赛事交付期一致 | 不含人脸和敏感信息时才可用于 PPT |
| `outputs/` | 私有 | 最短必要期限 | 只存聚合指标或已审查的演示产物 |
| `temp/` | 私有 | 生命周期规则自动删除，建议不超过 24 小时 | 默认不使用；如启用，必须记录原因 |

不要设置公共写入；不要在代码中拼接永久公开 URL；浏览器如需读取演示资源，应使用受限访问或短期签名 URL，并核对 CORS 来源。

## 5. 未来持久化设计（未批准、未实现）

只有在真实用户测试证明需要长期反馈或运营指标时，才考虑加入数据库。届时优先存**去标识的产品数据**，而不是原始视觉数据：

| 建议实体 | 用途 | 核心字段 | 不应存储的内容 |
|---|---|---|---|
| `evaluation_run` | 评测可复现 | `run_id`、模型、版本、时间、汇总时延 | 图片二进制、API Key |
| `evaluation_result` | 单个测试案例结论 | `run_id`、`case_id`、期望/实际摘要、判定 | 可识别地点、原始影像 |
| `feedback_item` | 匿名反馈与设计变更追踪 | 编号、场景、反馈摘要、采取措施 | 姓名、联系方式、录音原文 |
| `asset_registry` | 素材授权和删除追踪 | 对象键、授权编号、保留期限、负责人 | 身份证件、未脱敏合同附件 |

任何新增持久化实体都必须先补充：数据用途、最小字段、访问角色、保留期限、删除流程、导出范围和测试方案，并通过团队评审后再实现。

## 6. 隐私与质量检查清单

- [ ] 不上传或记录 API Key、OSS 临时令牌和 RAM AccessKey。
- [ ] 不把摄像头帧、完整视频、图像 Base64、OCR 原文或上游模型原文写入应用日志。
- [ ] 评测素材有授权编号和到期复核日期。
- [ ] 真实演示素材中无关人脸、车牌和私人信息已获得许可或完成处理。
- [ ] `temp/` 若启用，已配置自动删除规则并经过一次删除验证。
- [ ] 新字段同时更新 `backend/models.py`、前端类型、`接口契约.md`、测试和本文件。
