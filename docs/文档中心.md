# CityLens 文档中心

本目录记录 CityLens 的产品边界、工程契约、验证证据与交付过程。文档描述的是可复查的约定；除非 `项目进度.md` 或验收记录明确标为已完成，计划和待验证事项均不应被表述为已实现能力。

## 文档优先级与维护规则

1. `backend/models.py`、`frontend/src/types.ts` 和已通过的测试是当前接口字段的实现事实；`接口契约.md` 是对外协作契约。两者不一致时，先修复不一致再继续开发。
2. `产品需求文档.md` 是产品范围的事实来源；没有写入 PRD 的新功能不得在临近演示时直接加入主流程。
3. `架构决策记录.md` 记录“为什么这样做”；不要只在聊天记录或口头同步中保留重要理由。
4. 涉及真实用户、图像、视频、模型调用成本或云端权限的变更，必须同时检查 `数据模型与数据治理.md`、`测试策略与发布门槛.md` 和 `运维手册.md`。
5. 使用 RFC 2119 含义：**必须**表示发布前不可缺少，**应该**表示有充分理由才可例外，**可以**表示可选增强。

## 建议的变更流程

```text
用户问题 / 赛题要求
        ↓
PRD：确认目标、范围和验收条件
        ↓
Architecture + API + Data Model：确定边界与契约
        ↓
Test Strategy：先写可验证的测试点
        ↓
实现、评审、自动化测试
        ↓
真实模型 / 设备 / 用户验证
        ↓
PROGRESS + VALIDATION：记录事实与剩余风险
```

## 版本约定

- MVP 接口当前为 `v0.1`；任何破坏前端兼容性的 API 变化必须提高小版本并写明迁移方式。
- 文档顶部没有特别标注时，默认适用于仓库当前主分支。
- 所有真实密钥、含可识别信息的图像、原视频、访谈录音和私有 OSS 地址都不得写入本目录。
