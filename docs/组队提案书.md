## 1. 产品方向

### 1.1 一句话介绍

用影石相机采集城市步行画面，由多模态模型识别当前画面中清晰可见的障碍、道路设施与标牌文字，再用简短的中文语音告诉使用者"周围有什么、哪里需要注意"。

### 1.2 要解决的问题

在陌生或复杂的城市步行环境中，视障与低视力人群难以及时获得人行道障碍、道路设施和关键标牌的信息。现有手机读屏工具擅长读取屏幕文字，却不理解摄像头前的物理环境；而城市环境里真正影响当下行动的信息量很小、变化却很快——说多了是噪声，说错了是风险。

CityLens 要验证的不是"自动导航是否可用"，而是这个假设：

> 在一条预先选择、可控的城市步行路线中，经过优先级筛选的环境提示，能让目标用户更容易理解关键障碍、设施与标牌，且不产生明显的信息噪声。

### 1.3 提案的核心判断

这个方向上的竞争力不在"识别了多少类别"，而在下面四件事：

1. **把"不制造噪声"作为硬指标，而不是优化目标。** 单帧最多保留 3 个事件，每次最多播报 1 条，同类事件 8 秒内不自动重复，高优先级事件可以打断低优先级；识别失败或结果过期时**保持安静**，不朗读上一次内容。
2. **能力边界本身就是产品承诺。** 不测距、不做导航、不给通行判断，界面与演示材料始终保留"辅助理解工具，不替代导盲犬、白手杖和专业无障碍设备"的声明。单目画面只输出"前方／右前方／近处"这类相对表述。
3. **隐私默认最小化。** 前端不持有任何云端密钥；抽帧仅在用户明确同意后上传；应用日志不记录图像、视频、完整 OCR 文本或密钥；默认不写数据库、不存对象存储。
4. **影石设备落在采集侧的不可替代位置。** Link 2 承担实时输入与现场演示；X4 Air 承担全景路线素材采集，用于说明普通单目视角的盲区问题。**全景实时接入属于后续迭代，本次不作为已实现能力宣称。**

### 1.4 本次明确不做

- 不做自动驾驶式导航、转向指令、过马路许可或"可以通行"结论。
- 不承诺精确距离、碰撞预警、全天候识别率或替代专业无障碍设备。
- 不做用户档案、路线历史、位置追踪、人脸或身份识别。
- 不在 MVP 中训练、微调或本地部署大模型，百炼 API 是主推理路径。
- 不宣称 X4 Air 实时全景 SDK 已接入。

完整的范围定义与验收条件见 [产品需求文档](产品需求文档.md)。

## 2. 目标用户

| 角色                           | 需要完成的任务                                                       | 主要限制                                                       |
| ------------------------------ | -------------------------------------------------------------------- | -------------------------------------------------------------- |
| 视障或低视力体验者（核心用户） | 步行时获知近处障碍、台阶、斑马线、出入口等关键信息；主动读取一块标牌 | 语音不能频繁重复；不能把不确定内容说成事实；单手操作要有大按钮 |
| 现场演示者／陪同者             | 用 Link 2、手机摄像头或授权 MP4 展示完整闭环                         | 网络、设备权限和模型延迟存在不确定性                           |
| 团队测试者与评测者             | 用冻结的授权图片集和固定路线素材评估功能与失败表现                   | 不得收集无关人脸、行程与真实身份信息                           |

用户需求的来源是**计划中的三位目标用户匿名访谈**（每位约 20 分钟，聚焦"最近在陌生环境遇到的具体困难""障碍／入口／标牌的优先级""主动按键还是自动播报""重复与延迟的影响"）。访谈尚未执行，因此本节不包含任何虚构结论；记录表见 [验收记录](验收记录.md)。

设计上已经从公开的无障碍工程实践借鉴了通用原则（首屏单一主操作、状态不只靠颜色表达、清晰焦点、键盘可达、语音可暂停），而非复制某个产品的界面。

## 4. 技术路径

### 4.1 当前已实现的本地闭环

```text
浏览器（React + TypeScript）
    │  摄像头 / 本地 MP4 → 每 2 秒抽一帧 → 缩放 JPEG
    ▼  multipart JPEG
FastAPI 后端
    ├─ 输入限制：JPEG、大小、像素、来源检查
    ├─ 单请求并发控制：忙碌时返回 busy，不排队旧帧
    ├─ 百炼兼容视觉接口（样例供应商用于无密钥联调）
    ├─ Pydantic 严格校验：受限标签与字段
    └─ 规则引擎：模式过滤 → 优先级排序 → 去重 → 生成单条播报
    ▲  受控 JSON 响应
    │
浏览器  大字文字提示 + 中文语音队列（暂停 / 静音 / 重播）
```

四个关键工程决策：

1. **模型只负责"看见什么"，"说什么"由服务端规则决定。** 不采信模型自报的紧急度与播报文案，顺序与文案在 `rules.py` 内生成，避免把自由文本直接交给用户。
2. **最近一帧覆盖，不做请求排队。** 每个会话有独立 `session_id`，输入切换、暂停、拖动视频或进入后台都会作废旧结果，被取消的请求结果不得显示或朗读。
3. **密钥只存在于后端环境。** 前端构建产物、日志、仓库、截图里都不出现 `DASHSCOPE_API_KEY`。
4. **失败即安静。** 超时或 JSON 非法时不播报错误文本，也不回退到样例结果。

### 4.2 云化部署（规划，非当前能力）

```text
浏览器 / 现场设备
    │ HTTPS
    ▼
Nginx（ECS：TLS 终止、静态资源、反向代理）
    ├─ React 静态构建产物
    └─ FastAPI /api  →  百炼多模态 API
                     →  OSS（仅授权演示素材与可过期临时对象）
```

部署前必须完成：可信主机与 CORS 来源改为显式环境配置、后端端口不暴露公网、使用 RAM 角色访问私有 OSS Bucket、生产环境禁止 `sample` 伪装真实功能。详见 [架构与云端边界](架构与云端边界.md)。

### 4.3 全景增强路径（规划，非当前能力）

授权全景帧 → Panorama Adapter 切分为左前／正前／右前三个视角 → Vision Adapter（方向作为受控元数据）→ 复用现有 Observation 与规则流程。引入前必须确认导出格式、固定朝向、三视图的压缩与总延迟／费用，并为多图输入与故障回退补 API 与测试。

## 7. 风险与应对

| 风险                           | 影响             | 应对                                                                   |
| ------------------------------ | ---------------- | ---------------------------------------------------------------------- |
| 模型延迟高或权限不可用         | 现场演示失败     | 提供"只用按键识别"模式；准备已标注"演示录像"的备用流程                 |
| 单目模型给出不可靠的距离或方向 | 误导用户         | 只输出相对方位与近／中／远；服务端规则丢弃精确距离表述                 |
| 设备未按时到位                 | 无法体现影石价值 | Link 2 优先申请；演示至少保留手机／普通摄像头路径                      |
| 隐私质疑                       | 影响社会价值评价 | 默认不保存帧、不写日志、密钥仅在后端；明确能力边界声明                 |
| 只剩两天开发时间               | 交付不完整       | 收窄到固定路线五类目标，不新增类别；把"能连续稳定运行"作为唯一验收目标 |
