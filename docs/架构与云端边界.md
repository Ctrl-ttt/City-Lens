# CityLens 架构与边界说明

| 字段 | 内容 |
|---|---|
| 版本 | v0.1 |
| 更新日期 | 2026-09-22 |
| 适用范围 | 当前 React + FastAPI 原型，以及计划中的 ECS / OSS 部署 |

## 1. 当前实现与目标部署

必须区分“仓库已实现”和“可用于云端的目标架构”。当前实现已具备本地 React 前端、FastAPI 后端、样例供应商、百炼兼容接口适配、受限 JSON 校验、规则排序和浏览器语音队列；当前代码默认只信任 `localhost` / `127.0.0.1` 来源，**尚未把 OSS 作为运行时帧存储，也尚未完成面向公网 ECS 的域名、反向代理、可信主机和来源配置**。

```text
已实现的本地闭环

浏览器（React） ── multipart JPEG ──> FastAPI
      ↑                                  │
      └── 文字、状态、浏览器语音 <── 规则与受限响应
                                         │
                             样例供应商 / 百炼兼容 API


目标云端部署（须先完成部署项和测试）

浏览器 / 现场设备
        │ HTTPS
        ▼
Nginx（ECS：TLS、静态资源、反向代理）
        │
        ├── React 静态构建产物
        └── FastAPI /api
                 │
                 ├── 百炼多模态 API
                 └── OSS（仅授权演示素材、可选临时对象）
```

## 2. 组件职责

| 组件 | 职责 | 不承担的职责 |
|---|---|---|
| 浏览器前端 | 摄像头/视频输入、抽帧、会话隔离、显示、语音、用户控制 | 保存 API Key、作出导航或安全决策、长期保存图像 |
| `backend/app.py` | 输入限制、JPEG 清洗、来源检查、受控错误、单请求并发控制、静态资源服务 | 持久化用户画像、暴露供应商错误、将帧写日志 |
| `backend/vision.py` | 调用模型、约束提示词、解析 JSON、把上游错误映射为受控错误码 | 直接把自由文本输出给用户 |
| `backend/models.py` | Pydantic 严格数据模型、允许标签和字段限制 | 识别新类别而不更新契约 |
| `backend/rules.py` | 模式过滤、排序、去重、生成单条播报 | 推断地图方位、精确距离、通行安全 |
| 百炼 API | 对单帧进行视觉理解 | 提供持久会话、用户数据存储或可靠距离测量 |
| OSS | 授权的 Demo 视频、测试素材和必要的可过期临时对象 | 无差别记录所有实时帧或作为公开素材桶 |
| ECS / Nginx | HTTPS 入口、服务进程、受控网络边界 | 保存密钥到前端或绕过 RAM 最小权限 |

## 3. 单帧分析时序

```text
前端                后端                    百炼
 │  采集 JPEG         │                       │
 │ ─ POST /api/analyze ─────────────────────> │
 │                    │ 校验元数据、MIME、大小 │
 │                    │ 清洗 JPEG              │
 │                    │ ─── 图像 + JSON 提示 ─>│
 │                    │ <── 严格 JSON ──────── │
 │                    │ Pydantic 校验、规则排序 │
 │ <── 受控响应 ──────│                       │
 │ 显示、限频、播报    │                       │
```

关键约束：前端切换输入、暂停、拖动视频或切换模式时生成新 `session_id`；旧会话、过期帧或被取消请求的结果不得显示或朗读。后端不重试旧帧，也不把同一帧放入队列。

## 4. 全景增强路径（规划，不是当前功能）

X4 Air 全景素材建议使用独立的适配层，而不是将全景格式逻辑混入 API 控制器：

```text
授权全景帧
   ↓
Panorama Adapter（例如 py360convert）
   ├─ 左前视角
   ├─ 正前视角
   └─ 右前视角
   ↓
Vision Adapter（方向作为受控元数据）
   ↓
现有 Observation / Rules 流程
```

引入前必须完成：确认设备导出格式、确定相机固定朝向、压缩三张视图的大小、验证总延迟与费用，并为多图输入、方向元数据和故障回退添加 API 与测试。没有这些证据时，演示只应描述为前视画面理解。

## 5. 网络、密钥与数据边界

| 边界 | 必须遵守的规则 |
|---|---|
| 浏览器 → ECS | 使用 HTTPS；摄像头权限由用户在浏览器中主动授予；前端不拥有百炼或 OSS 管理密钥 |
| ECS → 百炼 | 仅后端使用 `DASHSCOPE_API_KEY`；密钥存在服务环境或密钥管理系统，不进入日志、仓库、截图或前端构建产物 |
| ECS → OSS | 优先使用 ECS 绑定的 RAM 角色；权限仅限指定 Bucket / 前缀；Bucket 保持私有 |
| 应用日志 | 只记录受控状态、事件数量、时延和错误码；不记录原始图像、视频、完整 OCR 文本、上游响应体或密钥 |
| 演示素材 | 只使用获得授权的素材；与实时帧分离存放；如需临时上传，必须有生命周期清理策略 |

## 6. 目标 ECS 部署前的必做实现项

这些项目是上线任务，不是当前已实现能力：

1. 将可信主机与 CORS 来源改为**显式环境配置**，只允许正式 HTTPS 域名和本地开发来源；为该配置增加拒绝未知来源的测试。
2. 让 Nginx 终止 TLS，仅将 `/api` 代理给本机后端端口；后端端口不直接暴露公网。
3. 使用运行时 RAM 角色访问 OSS；如果暂时无法使用角色，密钥只允许保存在 ECS 环境变量或密钥服务中。
4. 创建私有 OSS Bucket、受限 CORS 规则和 `temp/` 生命周期策略；不要将 Bucket 设为公共写入。
5. 将运行服务、模型名、域名、超时、日志级别与样例模式设置为环境配置；生产环境不允许 `sample` 伪装为真实功能。
6. 在 HTTPS 域名、手机摄像头、模型失败和备用视频条件下执行发布前测试。

## 7. 架构质量属性

| 质量目标 | 架构措施 |
|---|---|
| 安全与隐私 | 最小 RAM 权限、后端持有密钥、无帧持久化默认值、受控日志 |
| 可信提示 | 严格 schema、允许标签列表、服务端排序、禁止导航与精确距离表述 |
| 低复杂度 | 一次一个模型请求、单帧请求、无数据库依赖、样例供应商便于开发 |
| 故障可控 | 过期结果隔离、三次失败暂停、受控错误码、预录路线备用 |
| 可演进性 | 前后端共享概念模型、适配层隔离模型/全景差异、文档化变更流程 |

重要架构决定及其理由见 [架构决策记录](架构决策记录.md)。
