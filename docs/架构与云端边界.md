## 1. 当前实现与目标部署

必须区分“仓库已实现”和“可用于云端的目标架构”。当前实现已具备本地 React 前端、FastAPI 后端、样例供应商、百炼 HTTP 兼容接口与实时模型适配、受限 JSON 校验、规则排序和浏览器语音队列；当前代码默认只信任 `localhost` / `127.0.0.1` 来源，**尚未把 OSS 作为运行时帧存储，也尚未完成面向公网 ECS 的域名、反向代理、可信主机和来源配置**。

```text
已实现的本地闭环

浏览器（React） ── HTTP multipart 单帧 / WebSocket 连续帧 ──> FastAPI
      ↑                                                        │
      └────── 文字、状态、浏览器语音 <────── 规则与受限响应 ──────┘
                                                               │
                       HTTP：样例供应商 / 百炼兼容 API <────────┤
                       实时：最新待分析槽 → 云端串行单图 <───────┘


目标云端部署（须先完成部署项和测试）

浏览器 / 现场设备
        │ HTTPS
        ▼
Nginx（ECS：TLS、静态资源、反向代理）
        │
        ├── React 静态构建产物
        └── FastAPI /api
                 │
                 ├── 百炼多模态 API
                 └── OSS（仅授权演示素材、可选临时对象）
```

## 2. 组件职责

| 组件 | 职责 | 不承担的职责 |
|---|---|---|
| 浏览器前端 | 摄像头/视频输入、HTTP single-flight / 实时连续发送、背压跳过、最多 16 条无图元数据、会话隔离、显示/语音/取消/看门狗 | 保存 API Key、作出导航或安全决策、排队重传旧图 |
| `backend/app.py` | 输入限制、JPEG 清洗、来源检查、受控错误；实时接收任务 + 最新待分析槽 + 串行处理任务；共享模型锁、静态资源服务 | 持久化用户画像、暴露供应商错误、将帧写日志或积压多图 |
| `backend/vision.py` | HTTP 模型调用、约束提示词、解析 JSON、受控错误映射 | 直接把自由文本输出给用户 |
| `backend/realtime.py` | 无麦克风的合成 PCM/单图手动轮次、完整响应校验、历史删除确认与整体超时 | 云端生成期间持续送新图、保证供应商长期兼容或历史零影响 |
| `backend/models.py` | Pydantic 严格数据模型、允许标签和字段限制 | 识别新类别而不更新契约 |
| `backend/rules.py` | 模式过滤、排序、去重、生成单条播报 | 推断地图方位、精确距离、通行安全 |
| 百炼 API | 经 HTTP 或实时会话对本轮单图进行视觉理解 | 充当用户业务数据库、保证历史无影响或可靠距离测量 |
| OSS | 授权的 Demo 视频、测试素材和必要的可过期临时对象 | 无差别记录所有实时帧或作为公开素材桶 |
| ECS / Nginx | HTTPS 入口、服务进程、受控网络边界 | 保存密钥到前端或绕过 RAM 最小权限 |

## 3. 分析时序与实时协议边界

### 3.1 HTTP 单帧分析

```text
前端                后端                    百炼
 │  采集 JPEG         │                       │
 │ ─ POST /api/analyze >│                      │
 │                    │ 校验元数据、MIME、大小 │
 │                    │ 清洗 JPEG              │
 │                    │ ─── 图像 + JSON 提示 ─>│
 │                    │ <── 严格 JSON ──────── │
 │                    │ Pydantic 校验、规则排序 │
 │ <── 受控响应 ──────│                       │
 │ 显示、限频、播报    │                       │
```

HTTP 自动观察每 2s 尝试一帧且 single-flight，忙时跳过，不排队或重试旧图；主动看牌仍关闭实时连接，以较高分辨率单帧走 HTTP。HTTP 与实时共享全局模型锁，同一时刻只调用一个模型。

### 3.2 浏览器连续发送、后端最新槽、云端串行单图

**“实时连续帧流”只指浏览器 → 后端 WebSocket；不是云端双工、30fps 或多图 commit。**

```text
浏览器：ready 后约 1fps 持续发送，不等 result
    │ JPEG 1、2、3……
    ▼
receive_frames：校验/清洗 ──> Queue(maxsize=1)：只留最新待分析图
                                      │
                                      ▼
process_frames：取最新图 ──> RealtimeVision.observe(image)
                                      │
                            上传一张 → 生成 → 删除并等确认
                                      │
                            返回该图结果，再取下一张
```

`backend/app.py` 的 `receive_frames` 与 `process_frames` 是并行任务，不是云端输入与响应的并行：前者持续验证/清洗并替换旧待分析图，后者串行 observe。应用分析状态最多 **一张分析中 + 一张最新待分析**；生成、删除确认期间可以继续接收至后端槽，但不向云端发新图片。当前 ready 会话不会因自身生成而 busy；只有 HTTP 竞争全局模型锁时才因此 busy。第二条实时连接和 ready 前发帧另受独占锁/就绪检查拒绝。

例如正在分析 1，2 到达待分析槽后又被 3 替换，最终可返回 1、3，不返回 2。`result.frame_id` 是实际被选择分析的单图，不是多图 commit 的最新边界，也不保证是结果到达时浏览器最新发送的图。`latency_ms` 从该图后端接收起，包含清洗、槽等待、上传、响应与清理确认；前端按对应 capture 时间执行自动观察 6s / HTTP 看牌 8s 过期。

浏览器只在 ready、发送间隔 ≥1s 且无 WebSocket 背压时 capture；否则直接跳过、不积压。最多 16 条无图片的帧元数据用于结果匹配；取消/断开清空，不重传旧图。实时输入固定 session/source，frame_id 严格递增；JPEG 必须为编码后 ≤256KiB 的纯 base64，最多 1200 万像素，后端清洗最长边 960、质量 65；服务端接收间隔至少 0.9s。

### 3.3 真实云端协议：手动时序，不重叠输入

[官方 Python SDK](https://www.alibabacloud.com/help/en/model-studio/omni-realtime-python-sdk)明确要求手动模式（`turn_detection=null`，SDK 的 turn detection 关闭）在模型响应期间停止音视频输入。**先前“生成时继续向云端送图”的方案已被真实 API 证伪，不能宣称重叠输入已验证成功。** 实测在 `response.created` 后送图、`response.done` 后 commit 报 `buffer too small`；VAD 也会丢弃纯静音，不能在不采集麦克风前提下直接改 VAD 解决。

当前 `backend/realtime.py` 保持无麦克风、合成 PCM 静音：200ms 前导 → 单张图 → 1s 尾音 → `input_audio_buffer.commit` → `response.create` → 完整文本及 `response.done` 校验 → `conversation.item.delete` 并等待 `conversation.item.deleted`。全部结束才返回 observe、取下一张最新待分析图。1s 尾音及 delete/ack 是当前模型兼容实测，不是供应商稳定协议保证；删除确认不代表供应商不留存数据，也不能承诺历史绝不影响结果。

模拟上游可以验证本地调度、边界和错误处理，合成图真实请求只证明对应样例与模型组合的表现；两者均不能证明云端双工可用或真实摄像头准确率。2026-09-22 本轮 48 项浏览器 E2E 已通过，另完成合成摄像头到真实模型的页面检查，见[执行记录](测试策略与发布门槛.md#34-本轮执行记录2026-09-22)；真实摄像头与现场播报仍待实际验收。

### 3.4 超时、取消与恢复

- 后端每轮 generation 的上传、响应、删除确认整体限时 8s；前端 ready 最多等 15s，期间不 capture。
- 有待返回帧时，前端 9s 无有效新结果进展断开；继续发送、重复或无效匹配结果不会延长看门狗。可重试错误按 1/2/4s 最多重连 3 次，ready/result 不重置预算，重新开始才重置；恢复后只采新图。
- 后端等待下一张待分析图 30s 空闲关闭；会话 110min 上限在处理循环检查。断开或任一任务失败会取消接收与处理任务，释放连接和锁。
- 输入/模式/通道切换、暂停、停止、视频拖动、页面隐藏及 Link 2 控制均作废旧结果与语音、关闭实时连接；Link 2 控制期间禁止重新识别，确认画面稳定后手动开始。旧会话、过期帧或被取消请求的结果不得显示或朗读。

## 4. 全景增强路径（规划，不是当前功能）

X4 Air 全景素材建议使用独立的适配层，而不是将全景格式逻辑混入 API 控制器：

```text
授权全景帧
   ↓
Panorama Adapter（例如 py360convert）
   ├─ 左前视角
   ├─ 正前视角
   └─ 右前视角
   ↓
Vision Adapter（方向作为受控元数据）
   ↓
现有 Observation / Rules 流程
```

引入前必须完成：确认设备导出格式、确定相机固定朝向、压缩三张视图的大小、验证总延迟与费用，并为多图输入、方向元数据和故障回退添加 API 与测试。没有这些证据时，演示只应描述为前视画面理解。

## 5. 网络、密钥与数据边界

| 边界 | 必须遵守的规则 |
|---|---|
| 浏览器 → ECS | 使用 HTTPS；摄像头权限由用户在浏览器中主动授予；前端不拥有百炼或 OSS 管理密钥 |
| ECS → 百炼 | 仅后端使用 `DASHSCOPE_API_KEY`；密钥存在服务环境或密钥管理系统，不进入日志、仓库、截图或前端构建产物 |
| ECS → OSS | 优先使用 ECS 绑定的 RAM 角色；权限仅限指定 Bucket / 前缀；Bucket 保持私有 |
| 应用日志 | 只记录受控状态、事件数量、时延和错误码；不记录原始图像、视频、完整 OCR 文本、上游响应体或密钥 |
| 演示素材 | 只使用获得授权的素材；与实时帧分离存放；如需临时上传，必须有生命周期清理策略 |

## 6. 目标 ECS 部署前的必做实现项

这些项目是上线任务，不是当前已实现能力：

1. 将可信主机与 CORS 来源改为**显式环境配置**，只允许正式 HTTPS 域名和本地开发来源；为该配置增加拒绝未知来源的测试。
2. 让 Nginx 终止 TLS，仅将 `/api` 代理给本机后端端口；后端端口不直接暴露公网。
3. 使用运行时 RAM 角色访问 OSS；如果暂时无法使用角色，密钥只允许保存在 ECS 环境变量或密钥服务中。
4. 创建私有 OSS Bucket、受限 CORS 规则和 `temp/` 生命周期策略；不要将 Bucket 设为公共写入。
5. 将运行服务、模型名、域名、超时、日志级别与样例模式设置为环境配置；生产环境不允许 `sample` 伪装为真实功能。
6. 在 HTTPS 域名、手机摄像头、模型失败和备用视频条件下执行发布前测试。

## 7. 架构质量属性

| 质量目标 | 架构措施 |
|---|---|
| 安全与隐私 | 最小 RAM 权限、后端持有密钥、无帧持久化默认值、受控日志、无麦克风 |
| 可信提示 | 严格 schema、允许标签列表、服务端排序、实际被选帧归属与过期检查、禁止导航与精确距离表述 |
| 低复杂度 | HTTP single-flight；实时两任务 + 单个最新待分析槽、云端 observe 串行单图；无数据库依赖 |
| 故障可控 | HTTP 连续三次失败暂停；实时取消隔离、8s 整轮/15s ready/9s 无进展时限、1/2/4s 最多三次重连不重传；受控错误与预录备用 |
| 可演进性 | 前后端共享概念模型、适配层隔离模型/全景差异、文档化变更流程；兼容实测与官方协议、模拟测试与真实验收分别记录 |

重要架构决定及其理由见 [架构决策记录](架构决策记录.md)。
