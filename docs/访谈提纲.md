## 0. 执行前 60 秒读完

1. 三场共 30 题；每场约 20 分钟，★ 为底线题（全场共 9 题），时间不够先保 ★。
2. 问过去，不问愿望：先问"上次是什么时候"，再谈"你想要吗"。
3. 不现场演示产品（避免锚定回答），不承诺任何功能或时间点；被问"能不能做"一律回"记下来评估"。
4. 对方的批评就是数据：不辩解，逐条记录。
5. 每场结束立即口述要点互相备份；24 小时内回填本文结论区与验收记录表。

## 2. 共同话术

**开场（每场照念，约 1 分钟）**

> 我们是 insta 线下赛的学生队，在做"CityLens"原型：镜头拍前方，AI 把"眼前有什么"变成一句短中文语音，比如"右前方，共享单车"。它不导航、不判断能不能过马路，只描述。想请教您的真实经验，帮我们判断设计对不对。全程约 20 分钟，对外材料只用匿名编号；可随时打断或跳过任何问题；如需录音会在开始前单独征求您同意。

**收尾（每场）**

- 只能保留一种能力——只提醒障碍 / 只念牌子 / 只说周围有什么——您留哪个？
- 有什么我们该问没问的？

## 3. 场次 A · U01（视障 · 视障团队带头人）

**取证目标**：播报句式、重复节奏、静音策略的实现细节。她每天以读屏语音工作，是"听觉负载"的头号权威。

| # | 问题 | 验证的设计点 |
|---|---|---|
| A1 | 最近一次通勤在路面上停下来是因为什么？怎么发现的？ | 事实基线，填验收表"场景与困难" |
| A2 | 路面信息现在靠什么——杖、导航、问人、听声？各自最不放心的时刻？ | 缺口清单 |
| A3 | 整天听读屏语音：什么语速和节奏能听一天不累？现有导航 App 语音哪里最烦？ | TTS 语速、音色、打断策略 |
| A4 ★ | （念给受访者听）A："右前方，共享单车，占道。" B："注意，您右前方约三米处有一辆共享单车，请注意避让。"哪句第一时间反应得过来？B 里"约三米"您信吗？ | 12 字句式规范；不报米数 |
| A5 | 那辆自行车一直停在那，隔多久报第二次不烦？有更紧急的新提示时，该直接打断正在播的吗？ | 8 秒去重；优先级打断 |
| A6 | 走路时戴什么耳机？开放式/骨传导的真实体验？有没有"绝对不戴耳机"的路段？ | 开放式单耳设计（若否定需重议） |
| A7 | 最近一次找入口、门牌、会议室费劲是什么时候？念牌子这件事，想按一下再念还是它自己念？ | 看牌模式触发方式 |
| A8 | 您团队里新失明和先天失明的同事，对"机器说'可能/大概'"接受度一样吗？年长同事呢？ | uncertain 表述的分层 |
| A9 ★ | 机器没看清时，您要它说"没看清"，还是干脆不说？它说"可能有个台阶"，您敢信吗？ | 失败即静默（产品形态 §4 硬约束 5） |
| A10 | 收尾两问。 | 答辩素材 |

执行提示：先问经验再谈产品，全程不演示。

## 4. 场次 B · U02（视障 · 科技公司创始人）

**取证目标**：竞品格局、技术现实感、买单意愿，检验"这是 demo 还是产品"。

| # | 问题 | 验证的设计点 |
|---|---|---|
| B1 | 您作为创始人每天跑客户，路面信息缺口最大的一次具体是什么时候？ | 事实基线 |
| B2 | Be My Eyes、Seeing AI、国产各类 App 和硬件，真用过哪些？各自的死穴？哪个功能"就该这么做"？ | 竞品对照表 |
| B3 ★ | "走路时耳边主动、低频地报障碍"这个位置，在您用过的产品里有人占住吗？没有的话——是没人想到，还是被验证过不行？ | 定位唯一性 |
| B4 ★ | 云端多模态方案，您能接受的延迟上限是多少？网络不稳时宁可沉默还是报错？大模型"一本正经编一个不存在的障碍"，出现率到多少您会弃用？ | P90 目标；错误策略；幻觉容忍度 |
| B5 | 它说"可能有个台阶"还是干脆不说——您选哪个？ | 失败即静默（跨场交叉验证 A9） |
| B6 | 同样的镜头：装导盲杖上端、导盲犬鞍具、胸挂——您戴哪个？另外，手机后置摄像头平举是不是其实更现实？ | 三形态提案；是否漏了第四形态 |
| B7 | 做成产品的话心理价位是多少（一次性/订阅）？身边视障朋友普遍能接受的价格？ | BOM 与定价叙事 |
| B8 ★ | 假如您的公司立项做这个：第一个砍掉的功能是什么？最先把哪件事做到极致？ | MVP 范围裁剪 |
| B9 | 一个新辅助工具，从第一次试用到敢带它上路，中间要过几道坎？ | 信任建立路径 |
| B10 | 收尾两问 + 给学生团队一句最想说的话。 | 答辩素材 |

执行提示：预期会被狠批，不辩解，批评逐条记下。

## 5. 场次 C · U03（残疾人工作者 · 助残协会负责人）

**取证目标**：人群代表性、社会接受度、推广路径、公益叙事校准。她不是用户，不问走路细节。

| # | 问题 | 验证的设计点 |
|---|---|---|
| C1 | 从全国助残工作的视野看，视障群体城市出行最普遍、最没被解决的困难是什么？和"科技圈的想象"差最远的是哪个？ | PRD 问题定义 |
| C2 ★ | 先天失明、新失明、老年低视力、多重障碍——"一句 12 字语音 + 镜头朝前"的设计，哪类人群用不上？最容易被我们忽略的是谁？ | 用户范围与优先人群 |
| C3 | 辅助设备带镜头上街会拍到路人：从社区反馈看，视障用户和被拍路人各自的顾虑？我们设计了"不可关闭的镜头指示灯"，这够吗？ | 社会性设计（产品形态 §5） |
| C4 ★ | 这类产品要真正到达社区，一般走什么渠道——残联、协会、政府采购、公益捐赠？机构背书前必须看到什么证据？ | 推广路径与验收证据 |
| C5 | "只描述、不建议通行"这条线您怎么看？现实中用户过度信赖出了事，机构角度怎么看待这类风险？ | 边界声明 |
| C6 ★ | 您见过哪些"为残障人士设计"最后失败的产品？共性错误是什么？ | 反设计清单校准 |
| C7 | 答辩和公益评审场合，关于残障群体的表述哪些话您听了会觉得不对劲？该怎么换说法？ | 叙事措辞 |
| C8 | 学生原型阶段，协会愿意以什么形式参与——试用反馈、专家指导、场景对接？需要我们提供什么？ | 后续合作 |
| C9 | 如果只够服务好一小群人，该先服务谁——通勤上班族，还是老年低视力群体？ | 优先人群 |
| C10 | 有什么我们没想到但必须提醒的？ | 开放捕获 |

执行提示：措辞说"共同"不说"帮他们"；她的反应会校准答辩话术。

3. A9、B5 两题答案若与"失败即静默"冲突，提交架构决策记录说明取舍。
