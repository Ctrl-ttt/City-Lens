| 字段 | 内容 |

## 1. 测试目标

测试要回答五个不同的问题，不能互相替代：

1. **代码正确吗？**——单元与接口契约测试。
2. **页面完整闭环吗？**——浏览器端到端测试。
3. **模型在授权素材上可靠吗？**——冻结评测集与人工复核。
4. **设备、网络和语音在现场可用吗？**——人工设备与演练测试。
5. **产品边界安全吗？**——隐私、错误处理、可访问性与不作导航承诺的检查。

## 2. 测试分层

| 层级 | 覆盖对象 | 主要方式 | 通过标准 |
|---|---|---|---|
| 单元测试 | JSON 解析、标签白名单、排序、去重、会话隔离、语音队列 | Pytest、Vitest | 规则变更必须新增或更新相应测试 |
| API 契约测试 | `/api/health`、`/api/analyze`、`/api/realtime`、最新槽/跳帧、请求限制、错误壳、无密钥泄露 | FastAPI `TestClient` + 模拟上游 | 响应符合 `接口契约.md`；实时接收与串行生成分离，无效输入/上游异常受控 |
| 浏览器 E2E | 摄像头模拟、MP4、连续发送/背压/跳帧、取消、看门狗、有限重连、过期结果、窄屏布局 | Playwright + 本地样例 HTTP / 模拟实时服务 | 流程无页面错误或旧结果；不以模拟服务证明真实云端协议 |
| 真实模型评测 | 授权冻结图片、模型名、识别结果和时延 | 人工标注 + 百炼真实调用 | 结果记录可复查，不将调试结果混入冻结集 |
| 人工设备测试 | Link 2、X4 Air 素材、中文语音、手机/演示电脑、网络中断 | 检查表和录屏 | 每项有日期、设备、操作者和结果 |
| 安全与无障碍检查 | 密钥、日志、权限、焦点、键盘、屏幕阅读器、错误文本 | 人工审查 + 自动检查 | 不暴露敏感数据；核心操作可完成 |

## 3. 自动化测试设计

### 3.1 后端

后端测试至少覆盖（要求清单，不代表本轮已执行通过）：

- 允许的类别、标签、方向、文本长度与未知字段拒绝；行走与看牌模式过滤；
- 自动标牌 OCR 用合成输入/模拟模型验证 HTTP 与实时 walk 纳入可读标牌、read 仅最清晰一项、clarity 严格校验及 low 排除、台阶/其它障碍/high 标牌/medium 标牌/设施稳定排序、文字空白规范化后跨方向及清晰度去重、walk 三项/read 一项上限与仅首项播报；模拟验证不证明真实摄像头 OCR 准确率；
- 模型返回 Markdown 围栏 JSON、无效 JSON、超长输出和未定义字段；认证、限流、不可用、超时、网络错误和内部错误的受控响应；
- HTTP JPEG MIME、文件大小、像素限制、字段重复和元数据校验；HTTP 竞争模型锁时 `429 busy`，不排队旧帧；
- 实时纯 base64 JPEG ≤256KiB（编码后）、总消息限额、≤1200 万像素、清洗最长边 960；固定 source/session、frame_id 严格递增、0.9s 服务端间隔边界；
- `receive_frames` 与 `process_frames` 两任务：阻塞第 1 帧生成或删除确认时仍可接收第 2、3 帧，`Queue(maxsize=1)` 以 3 替换 2；最多一张分析中 + 一张最新待分析，自身生成不让接收 busy，与 HTTP 竞争才 busy；第二条实时连接或 ready 前发送仍受独占/就绪约束；
- 结果只属于实际选中的单图：返回 1、3 且不分析 2；`latency_ms` 从对应帧后端接收起计入清洗、槽等待、上传、响应和清理，而非多图 commit 最新边界；
- `RealtimeVision.observe(image)` 串行执行：合成 PCM 200ms 前导 + 一张图 + 1s 尾音、commit/生成、完整输出校验、`conversation.item.delete`/ack；生成及清理确认期间禁止新图片上云，不能让 mock 的宽松行为重建已证伪的云端重叠输入；
- 单轮上传/响应/清理整体 8s 超时；30s 等待下一帧空闲、110min 会话期限；客户端断开、输入错误、上传/生成/删除确认失败或超时均取消两个任务、清空待分析状态并释放锁，无旧图重传；
- 响应、日志和健康接口均不泄露密钥、图片、OCR 全文或上游错误正文。

### 3.2 前端与浏览器流程

前端及新版 E2E 至少覆盖（未运行并记录前不得勾选通过）：

- **仅 HTTP** 每 2s 尝试抽帧、single-flight，忙时跳过；手动看牌继续使用较高分辨率 HTTP；
- 实时自动观察在 ready 后 1fps 持续发送，扣住结果 1 时仍发 2、3；支持返回 1、3 跳过 2，结果匹配实际被分析图而非多图 commit 边界；
- 实际发送间隔 ≥1s；未 ready 或 `bufferedAmount>0` 时不 capture、不排队；最多 16 条纯元数据、不持有图片，淘汰后不再接受相应结果；
- ready 15s 超时；有待返回帧时 9s 无有效新结果进展即断开，持续发送不能延期；外会话、未发送、重复、倒序结果不算进展；有效结果刷新看门狗，已无待返回帧时清除；
- `result.frame_id` 对应的 capture 起自动观察 6s / HTTP 看牌 8s 过期，不能用其它帧、握手或结果到达时间续期；过期不显示、不进入语音队列；
- 可重试错误按 1/2/4s 最多重连 3 次，ready/result 不重置预算，error+close 不重复消耗次数；重新开始才重置；连接恢复不重放旧图；
- 输入、模式、通道、暂停、停止、视频拖动/结束、页面隐藏及 Link 2 控制取消旧工作，清除结果/语音/元数据并关闭连接；迟到消息无效、已安排的重连可取消；Link 2 指令期间不能重启识别；
- HTTP 连续三次失败后自动暂停；实时连接错误按独立的有限重连规则处理，不能套用 HTTP single-flight/失败计数替代；
- 同一提示 8 秒内不自动重复，手动看牌绕过去重；高优先级可中断低优先级播报；静音、停止和会话切换清空待播内容；
- 390 px 窄屏无水平溢出，关键按钮在用户确认前不可用。

## 4. 真实模型评测设计

真实模型评测流程：

```text
取得素材授权
        ↓
建立匿名 case_id 与人工预期
        ↓
将调试集与冻结集分开
        ↓
冻结提示词、模型名、规则版本
        ↓
运行真实模型并记录结果、时延、错误
        ↓
人工复核“漏报、无依据内容、错误文字、错误方向”
        ↓
记录结论；不得事后修改人工预期
```

### 4.1 最小测试集

| 类别 | 建议数量 | 例子 | 重点风险 |
|---|---:|---|---|
| 障碍物 | 10 | 单车、围挡、路障、台阶 | 漏报近处风险、重复播报、错误方向 |
| 道路设施 | 10 | 斑马线、电梯、出入口、公交站 | 把设施说成通行许可 |
| 看牌文字 | 10 | 路牌、门牌、楼层、指示牌 | 幻觉补字、数字或路名错误 |
| 空白/模糊 | 10 | 模糊、遮挡、无相关目标 | 虚构障碍、虚构文字、无依据建议 |

其中每类至少 5 张可用于调试，另 5 张冻结。MVP 的小样本内部目标与记录模板见 [验收记录](验收记录.md)，不能把该目标宣传为正式识别准确率。

### 4.2 关键指标

| 指标 | 定义 | MVP 目标 |
|---|---|---|
| 核心信息命中 | 冻结任务图中，是否提取到人工预期的关键事件/文字 | 至少 12/15 张任务图命中核心信息 |
| 无依据内容 | 空白/模糊图中捏造事件、文字或通行结论的数量 | 5 张空/模糊图为 0 条虚构安全结论 |
| OCR 核验 | 关键路名、数字、楼层逐字人工核对 | 不确定时必须报“不清晰”而非补全 |
| 端到端时延 | 从前端取帧到前端收到结果的耗时 | 至少 30 次真实请求，P90 ≤ 5 秒 |
| 失败率 | 认证、限流、网络、超时、输出无效等失败 / 总请求 | 单独列出，不通过删除慢请求掩盖 |

实时耗时必须按实际返回的 `frame_id` 对应 capture 起算，另列服务端 `latency_ms`（自该帧后端接收起，含最新槽等待与清理）。记录发送/被选择/跳过数量，不把正常最新槽替换当作模型失败，也不因跳帧而隐去超时或错误。

### 4.3 真实协议反证与证据边界

**浏览器 → 后端连续帧流不等于云端双工或 30fps。先前云端重叠输入方案已被真实 API 证伪，禁止再标为“已真实验证成功”。** [官方 Python SDK](https://www.alibabacloud.com/help/en/model-studio/omni-realtime-python-sdk)要求手动 `turn_detection=null` 在生成期间停止音视频输入。真实测试在 `response.created` 后送图、`response.done` 后再 commit 失败 `buffer too small`；VAD 模式也丢弃纯静音，不能在不采集麦克风前提下直接改 VAD 解决。

当前保持合成 PCM（200ms 前导 + 每图 1s 尾音）、无麦克风，按单图上传 → 生成 → 清理/确认后再取最新图。尾音与 `conversation.item.delete`/ack 属当前模型兼容实测，不承诺供应商稳定或历史绝不影响结果；真实回归应检查连续不同标牌及空白图的历史串扰，而不能仅凭删除 ack 判定无串扰。

自制标牌图、空白图及合成摄像头的真实请求仅提供对应合成素材的能力证据；模拟模型及浏览器回归只验证软件规则/交互。本轮新版 E2E 和合成输入真实模型检查已执行，范围与结果见第 3.4 节。**真实摄像头、现场 OCR 和中文语音听感验收仍未完成**，须另行记录设备、素材、日期与结果；旧 mock 对重叠输入的支持不是供应商协议证据。

## 5. 现场与异常场景矩阵

| 编号 | 场景 | 预期结果 |
|---|---|---|
| M-01 | 摄像头权限被拒绝或设备被拔出 | 明确错误、释放资源、可重试，不继续播旧结果 |
| M-02 | 视频拖动、切换相机、切换看牌模式 | 旧请求/实时任务取消，旧结果不显示或播报；看牌仍走 HTTP |
| M-03 | API Key 缺失、认证失败或模型限流 | 显示受控中文错误，无样例回退，无密钥泄露 |
| M-04 | 超时或网络断开 | 当前帧作废；HTTP 连续三次失败暂停；实时按 15s ready / 9s 无进展看门狗及 1/2/4s 最多三次重连处理，不重传旧图 |
| M-05 | 同一单车持续出现在多帧 | 8 秒内不重复语音 |
| M-06 | 低优先级设施提示后出现台阶 | 台阶提示优先，可中断低优先级语音 |
| M-07 | 无中文可用语音 | 页面保留文字并说明语音不可用；不假装已播报 |
| M-08 | 键盘和屏幕阅读器操作 | 确认、启动、暂停、静音、重播、停止均可达且状态可读 |
| M-09 | 连续运行 10 分钟 | 无多图队列或语音积压；实时最多 16 条无图元数据、后端一张分析中 + 一张最新待分析；停止后可恢复 |
| M-10 | 实时链路失败 | 明确失败；用户可手动切换 HTTP 或标注的预录路线备用，不自动回退样例 |
| M-11 | 第 1 帧生成/清理慢，第 2、3 帧继续到达 | 后端保持接收、3 替换 2，云端只在第 1 轮完全结束后分析 3；结果与 capture 时间分别对应 1、3 |
| M-12 | WebSocket 背压、暂停/隐藏或 Link 2 控制 | 背压不 capture、不排队；其它操作清理连接、重连定时器和旧提示，设备稳定后再手动开始 |

## 6. 发布质量门槛

任何演示或部署版本至少需要；以下是待核对门槛，本文更新不代表已通过：

- [ ] 自动化测试、前端构建均通过，记录当前版本与命令；新版连续帧 E2E 未实际完成前不得沿用旧版通过结论；
- [ ] HTTP 2s single-flight / 手动看牌与实时最新槽语义分别验收；实时覆盖跳帧、取消、背压不 capture、元数据上限、看门狗、有限重连与无旧图重传；
- [ ] 云端 observe 串行单图，生成/删除确认期间无新图上传，单轮上传/响应/清理整体 8s；HTTP 竞争及退出后锁释放通过测试；
- [ ] `.env`、日志、截图和提交记录中无真实密钥；
- [ ] API 与数据模型文档和实现一致，result 帧归属/latency 起点/capture 过期语义无混淆；
- [ ] 真实模型权限使用一张授权图片验证成功；实时手动时序与连续不同场景的历史串扰另有实测记录，合成图不冒充真实摄像头验收；
- [ ] 已完成一次设备、语音、网络异常和备用视频彩排；
- [ ] 已记录当前模型、规则版本、测试日期、设备和已知限制；
- [ ] 文案明确浏览器→后端连续流与云端串行边界，无“云端重叠输入已真实验证成功”、30fps、历史绝无影响等承诺；无精确测距、自动导航、通行许可或替代专业辅助设备宣称。

## 7. 缺陷分级与处理

| 级别 | 示例 | 处理要求 |
|---|---|---|
| P0 | 泄露密钥、把样例当真实识别、持续播放旧风险提示、输出通行许可 | 停止演示或发布，立即修复并复测 |
| P1 | 关键按钮不可用、模式混淆、模型错误未受控、现场主流程失败 | 本次发布前修复，或移除受影响能力 |
| P2 | 单个标签顺序、文案、非核心视觉问题 | 记录并安排后续版本 |
| P3 | 不影响使用的样式或文档问题 | 合并到维护任务 |
