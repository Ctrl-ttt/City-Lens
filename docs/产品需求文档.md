## 1. 问题与目标

在陌生或复杂的城市步行环境中，用户可能难以及时获取人行道障碍、道路设施和关键标牌信息。CityLens 使用影石设备或普通摄像头采集画面，借助多模态模型把**当前清晰可见的环境事实**转为简短的中文文字和语音提示。

MVP 要验证的不是“自动导航是否可用”，而是以下假设：

> 在一条预先选择、可控的城市步行路线中，经过优先级筛选的环境提示，能让目标用户更容易理解关键障碍、设施和标牌信息，且不会产生明显的信息噪声。

## 2. 用户与使用场景

| 角色 | 需要完成的任务 | 主要限制 |
|---|---|---|
| 视障或低视力体验者 | 在步行时获知近处障碍、台阶、斑马线、入口等关键信息；主动读取一块标牌 | 语音不能频繁重复，不能把不确定内容说成事实 |
| 现场演示者 | 通过 Link 2、X4 Air、手机摄像头或授权 MP4 展示完整闭环 | 网络、设备权限和模型延迟存在不确定性 |
| 团队测试者 | 使用冻结的授权图片和固定路线素材评估功能 | 不应收集无关人脸、行程和真实身份信息 |

## 3. MVP 范围

### 3.1 必须具备

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-01 | 明确告知用户当前是样例模式还是真实识别模式，并在获取摄像头或上传帧前取得用户操作确认 | 未确认时不能开始识别；样例结果不会被伪装为真实结果 |
| FR-02 | 支持摄像头或本地 H.264 MP4 的单帧抽取；前端每次只提交一张 JPEG | 输入切换、暂停、拖动视频后，旧结果不可继续显示或播报 |
| FR-03 | 提供“行走模式”和“看牌模式” | HTTP 与实时行走模式均返回障碍、设施及可读路牌/门牌/方向指示牌；看牌仍用较高分辨率 HTTP，只返回最清晰的一块标牌，不含障碍或设施 |
| FR-04 | 对图片调用已配置的百炼视觉模型，并将结果校验为受限 JSON | 模型输出不能额外携带导航指令、精确距离或未定义字段；标牌必须提供非空 clarity，low 不进入事件或播报 |
| FR-05 | 对事件排序、去重、限量并生成一条可播报提示 | 行走单帧最多 3 项、看牌最多 1 项；每帧仅首项可播报；相同提示 8 秒内不自动重复，手动触发绕过去重 |
| FR-06 | 用大字体显示最近提示，并提供暂停、静音、重播和键盘可达的控制项 | 暂停或静音必须立即停止后续语音；屏幕阅读器能读出状态变化 |
| FR-07 | 对未配置、认证失败、限流、超时、网络异常和无效模型输出提供可理解的失败状态 | 不朗读上一次结果，不显示供应商原始错误，不自动回退到样例识别 |
| FR-08 | 准备一段经过授权的固定路线预录素材作为现场备用 | 实时演示失效时，可切换到明确标注为“演示录像”的备用流程 |

### 3.2 本次不做

- 不提供自动驾驶式导航、转向指令、过马路许可或“安全通过”结论。
- 不承诺精确距离、碰撞预警、全天候识别率或替代导盲犬、白手杖、专业无障碍设备。
- 不做持续保存的用户档案、路线历史、位置追踪、人脸识别或身份识别。
- 不在 MVP 中训练、微调或本地部署大模型；百炼 API 是主推理路径。
- 不承诺 X4 Air 的实时全景 SDK 已完成接入。当前全景多方向分析是后续增强，须在实现与设备测试后才能宣称可用。

## 4. 核心用户流程

### 4.1 行走模式

```text
用户确认提示与摄像头权限
        ↓
启动识别，系统按节流规则抽取当前帧
        ↓
后端返回受限事件 JSON
        ↓
规则引擎排序、去重、只选最高优先级播报
        ↓
页面显示文字并尝试中文语音播报
        ↓
用户可暂停、静音、重播或停止并释放输入
```

HTTP 当前使用 `qwen3-vl-plus`，每 2 秒尝试抽帧且 single-flight，忙时跳过。实时默认模型为 `qwen3.5-omni-plus-realtime`；自动观察在后端 ready 后约 1fps 持续向后端 WebSocket 发新帧，不等待结果。未 ready、节流或客户端背压时不 capture、不排队，最多留 16 条无图片的帧元数据。两条链路均自动提取可读标牌，无需先按“看牌”；采样间隔不是响应时延保证。

**实时连续帧流仅指浏览器 → 后端，不是云端双工或 30fps。** 后端 `receive_frames` 持续校验/清洗并用 `Queue(maxsize=1)` 替换旧待分析图；`process_frames` 取最新图串行调用 `RealtimeVision.observe(image)`。最多一张分析中 + 一张最新待分析；生成和删除确认期间仍接收，但不向云端发新图，自身生成不会让接收 busy，与 HTTP 竞争模型锁才 busy。结果帧号是实际选中分析的图，可返回 1、3 而跳过 2，不是多图 commit 的最新边界；没有旧图重传。

[官方手动时序](https://www.alibabacloud.com/help/en/model-studio/omni-realtime-python-sdk)要求 `turn_detection=null` 时生成期间停止音视频输入。真实测试在 `response.created` 后送图、`response.done` 后 commit 失败 `buffer too small`；VAD 也丢弃纯静音，不能在无麦克风前提下直接改 VAD 解决。当前保持合成 PCM 静音（200ms 前导 + 每图 1s 尾音）、不采麦克风，按“上传一张 → 生成 → 删除并等确认 → 取最新图”运行。尾音及 `conversation.item.delete`/ack 只是当前模型兼容实测，不承诺供应商长期稳定或历史绝不影响结果。

### 4.2 看牌模式

```text
用户点击“看牌”
        ↓
暂停自动环境分析并关闭实时连接，取较高分辨率当前单帧
        ↓
通过 HTTP 只读取最清晰的一块标牌，不返回障碍或设施
        ↓
文字可确认：显示并播报
文字不清晰：提示调整角度，不臆测补全
```

## 5. 业务规则与安全边界

1. 模型只能报告当前画面中清晰可见的事实；不确定时返回“无法确认”或空结果。
2. 事件顺序为 `stairs`/`step` → 其它障碍 → high 标牌 → medium 标牌 → 公共设施，同级保持原顺序；行走模式自动纳入可读路牌、门牌及方向指示牌，看牌仅保留最清晰的一项标牌。
3. 对单目/普通 RGB 画面只使用相对方向表述，如“前方”“右前方”；不做距离估计，不得生成“约 3 米”等距离。
4. `left/front/right` 指的是未镜像相机画面中的相对方向，不是地图方位或用户绝对朝向。
5. 所有语音都是辅助理解提示，界面和演示材料都必须保留“不替代专业无障碍设备”的边界声明。
6. 无法分析时，要明确提示系统不可用；不得继续播放旧事件，也不得输出通行建议。
7. `Observation.clarity` 严格为 `high`、`medium`、`low` 或 `null`；`text/sign` 必须提供非空枚举值，非文字事件只可省略或为 `null`。high 表示大字、干净且完整清楚可读；medium 表示较小但所选文字仍完整可读；low 表示模糊、缺字或不确定，由服务端从事件与播报中排除。这只是模型视觉定性判断，不是距离或经校准的准确率。
8. 标牌按规范化空白后的相同文字去重，忽略方向与清晰度，排序去重后行走最多显示 3 项、看牌最多 1 项。标牌语音键为 `sign:<text>`，其中 `<text>` 为规范化后的文字；自动播报 8 秒去重不变，手动触发绕过去重。
9. 每帧只有首项事件可生成播报：障碍 `high` 可打断，标牌 `normal`，设施 `low`。重复首项障碍被抑制时不改播同帧标牌，标牌可能等待后续帧才被选为首项；不能承诺所有显示事件都会被朗读。

## 6. 非功能要求

| 维度 | MVP 要求 |
|---|---|
| 延迟 | 真实请求 capture 到返回的端到端 P90 目标 ≤5s，未达标改用按钮触发；“实时”仅是传输通道名称，不是时延保证。自动观察 capture 起 6s、HTTP 看牌 8s 过期；实时 latency_ms 从实际被选帧后端接收起计，含槽等待和清理 |
| 并发 | 后端全局一个模型调用；HTTP 每 2s single-flight，竞争时 busy；实时接收持续更新一个最新待分析槽，自身生成不使接收 busy，不积压多张待分析图 |
| 时限与恢复 | 后端单轮 generation 含上传/响应/清理整体 8s；前端 ready 15s，有待返回帧但 9s 无有效新结果进展断开；可重试错误按 1/2/4s 最多重连 3 次，ready/result 不重置预算，无旧图重传；后端等待新待分析图空闲 30s、会话限 110min |
| 图片与元数据 | HTTP JPEG ≤2MiB；实时纯 base64 JPEG 编码后 ≤256KiB，清洗最长边 960，客户端 ≥1s / 服务端 ≥0.9s 间隔；同连接 source/session 固定、frame_id 严格递增；均受像素限制，不在日志记录帧或 OCR 原文 |
| 隐私 | 实时帧只短暂分析或等待最新槽，默认不写数据库、不存 OSS、不采麦克风；上游 delete/ack 不承诺供应商无留存或历史绝不影响结果；录像和访谈须单独授权 |
| 取消与设备 | 暂停、输入/模式/通道切换、拖动、页面隐藏及 Link 2 控制作废旧结果/语音、关闭实时连接；Link 2 指令期间禁止识别，稳定后手动重新开始 |
| 可访问性 | 清晰焦点、大字号高对比、键盘可达、状态可读、语音可暂停/静音/重播 |
| 可维护性 | 字段有契约、规则有单元测试、真实模型评测与样例测试分开记录 |

## 7. 成功标准

MVP 通过并不等于可以用于真实道路独立出行。自动标牌 OCR 的合成输入/模拟模型自动化验证只检查软件规则，合成图真实调用也不证明真实摄像头 OCR 准确率或云端重叠输入可行。本轮最新槽调度版本的 48 项浏览器 E2E 已通过，见[执行记录](测试策略与发布门槛.md#34-本轮执行记录2026-09-22)；以下真实场景目标仍待人工验收，不能因自动化通过或文档更新而标记完成。最小成功标准是：

1. 在一条固定路线中完成“启动 → 障碍/自动标牌/设施提示 → 主动看牌 → 停止”的完整演示；
2. 冻结评测集中，至少 12/15 张任务图提取到预期核心信息，且 5 张空白或模糊图不虚构障碍或通行结论；
3. 完成至少 30 次真实模型请求并记录端到端时延、失败次数和 P90；
4. 收到至少 3 位目标用户或相关体验者的匿名反馈，并记录反馈如何影响设计；
5. 实时演示、预录备用、设备权限和语音暂停均经过人工检查。

具体证据记录在 [验收记录](验收记录.md)，项目状态记录在 [项目进度](项目进度.md)。
